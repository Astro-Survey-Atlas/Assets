# 后台巡天归组与发布前检查

数据总览和审核产品使用同一份后台清单：公共目录中的产品，加上编辑存储中已登记的产品。
按产品的 `surveyId` / `releaseId` 归组；尚未公开的巡天会自动生成后台分组。
草稿、已审核、已发布、已退休是产品状态，不能用“是否出现在公共 Catalog”替代。
后台分组不修改产品身份、revision、审核记录或公开发布快照。

## 2026-09-20 查明的不一致

此前审核页将没有公共 Catalog 对应记录的产品放进 `__unmatched__`，数据总览摘要
只复制 `releases`，未复制该兜底分组的 `unmatchedProducts`，导致出现空分组和漏项。
当时漏项为 3 个 JWST 草稿（Carina NIRCam、SMACS0723 NIRCam、F115W beta）和
1 个已退休 AKARI FIS 产品。它们已经登记了 `jwst` / `akari` 身份，缺的只是后台分组展示。
AKARI 的退休源于实际原生 MOC O0，不会因后台归组而重新公开。

JWST 现在按已有身份显示两个集合 `dr1` / `public`。保留原登记名称，不据此宣称
它们是 JWST 官方统一 DR，也不宣称单个观测场代表全部 JWST 覆盖。

## 新增巡天分组

1. “任务 → MOC 探索”新建探测，不绑定已有产品，使用统一的巡天名称，例如 `JWST`。
2. 核对候选的来源、观测范围与数据性质，选择合适候选进行构建。
3. 完成构建后“登记为产品”。登记继承探索任务的巡天身份及集合事实，后台自动归组；
   已登记产品不需要为了显示分组重新扫描、构建或登记。
4. 产品详情检查来源、产物和原生阶数，审核当前版本，再在发布计划提交。
   只有完成正常发布流程后，产品才会进入公开目录与资源包。

同名或标题相似不等于同一巡天。系统不按候选标题猜测归属，也不提供绕过证据和审核的
拖拽改组。确实登记错身份时，应先核实原探索任务与构建绑定，不能只改展示名称冒充归组。
CSST 私有数据仍不得登记进 Assets。

## 发布门禁

产品详情按需调用只读 `GET /api/v1/admin/products/:id/preflight`，返回当前 revision
与 `nativeOrder` 检查结果。检查已锁定的实际 MOC 字节和 SHA256，解码 NUNIQ 后要求
最高原生 order ≥ 4。尚未发布的 STAGED 构建可以直接检查，不准备候选、不发布或修改记录。
缺少文件、哈希不一致、解码失败或精度不足均不能显示通过；请求失败保持按钮禁用。
后端审核、发布计划和冻结候选仍重新执行已有的精度检查，不信任浏览器检查结果。
混合阶数 MOC 可包含粗阶内部像元；不能用 requested maxOrder 或放大的预览达标。

发布计划加载及刷新显示转圈和 `aria-busy`，期间禁用刷新、提交。刷新保留旧表格与勾选，
失败显示错误；后续提交仍由后端校验计划和基线版本。加载动画不表示有确定完成百分比。

## 退休产品重新发布

退休与公开撤下是两个步骤。退休后详情显示“待发布撤下”或“已撤下”，以当前公开快照
是否仍包含产品为准。退休不会直接删除已公开资源；点击“发布撤下”提交正常发布队列，
等待网站核验完成后才可恢复。相关发布任务仍在执行时，“恢复为草稿”保持灰色禁用。

1. 在审核产品中打开已退休产品；若为“待发布撤下”，先点击“发布撤下”。
2. 状态为“已撤下”后，点击“恢复为草稿”，填写恢复原因。
3. 恢复保留 productId、巡天及集合身份，revision 递增，清除旧审核。退休原因、恢复原因
   和时间保留在历史中；不会自动公开，也不会恢复旧快照。
4. 校验已有真实 MOC，或从真实来源选择候选并构建。必须有明确绑定且通过 SHA/解码
   校验的原生 MOC，最高实际 order ≥ 4；旧 O4 预览不能代替原生文件。
5. 检查来源与限制，重新审核当前版本，再发布。资源包版本在撤下期间保留递增记录，
   后续重新发布不会重用这次撤下前的包版本。

管理接口为 `POST /api/v1/admin/products/:id/restore`，请求体
`{"revision":当前版本,"reason":"恢复原因"}`，沿用管理鉴权。缺少字段返回 400，
版本冲突、未退休、仍在公开目录或相关发布任务未结束返回 409。拒绝公开的巡天不能恢复。
恢复后的产品若没有绑定原生 MOC，审核、发布计划和候选构建均拦截，不能复用历史空几何审核。

SDSS DR9 color imaging 的历史 O4 概览不是可验证的原生 MOC；天球中正常显示的
DR9 g-band 是另一个产品。恢复 color 产品仍需补齐其自身来源与覆盖，不得借用 g-band 身份。
