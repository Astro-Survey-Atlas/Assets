# Astro Survey Atlas · UI 设计说明 v3

## 设计目标

第一次访问的人应当看懂三个问题：项目能回答什么，如何开始，最后得到什么。

首页的主要解释为：“看一片天空有哪些公开观测，比较巡天共同覆盖的区域，再找到对应的数据单元与官方获取入口。”流程为“选天空 → 比较共同覆盖 → 整理数据来源”。结果是可追溯的来源清单，保留巡天、版本、产品、原生单元、精度与访问入口。

## 视觉语言

点阵作为界面的结构语言：规律的背景点、单元边界、叠加覆盖、十字定位、细线连接和少量方形状态标记。图形承担解释任务。主视觉为局部空间索引图，不使用星云、银河图片、粒子云、光晕或大面积发光渐变。

点阵可以启发视觉风格；业务中的 HEALPix / MOC 必须保留真实几何和精度。概念图使用“空间索引示意”标注，不能作为真实数据层。

原 Logo 使用仓库中的完整官方 PNG，保留蓝色电路线、红色天球及原字标。两主题共用原文件，无重描、滤镜、反白或换色。深色主题用小块白色品牌底板保持可读性。

## 首页布局

1. **用途标题与行动入口。** 左侧两行标题“以天空为索引，找到巡天数据。”，右侧解释用途并提供探索天空、浏览巡天两个入口。
2. **宽幅图解。** 以蓝、红两个覆盖图层和共同覆盖单元说明空间关系，用实线选区和连接线指向来源身份。右侧短文解释区域、观测与获取入口之间的关系。
3. **横向操作路径。** 用连续编号讲清选择巡天、比较覆盖、整理来源三个步骤。
4. **来源清单预览。** 展示真实支持的原生单元类型及来源字段，让用户了解最终产出。保留估算和库存限制，不填入虚构查询结果。
5. **巡天登记列表。** 按行组织巡天、数据类型、原生单元与支持范围，便于快速浏览。
6. **项目与开发者入口。** Assets / Warehouse / Workspace 的职责和 API 信息放在下方，先让访客理解使用目的。

## 天球工作页布局

任务标题直接问“这片天空，有哪些观测？”。工具栏区分浏览覆盖、比较共同区域两个模式，避免把每次地图点击都暗示成文件级查询。

地图使用宽幅局部投影构图，桌面图层面板以紧凑浮层呈现，实线边界强调选区。地图下方集中显示来源列表，列出巡天 / 版本、原生数据单元、产品、空间依据与官方入口。导出操作与来源表放在一起，并明确导出 JSON / CSV 清单。

手机界面将图层移到地图上方，保持选区完整可见；来源行改成竖向字段，使原生身份、精度说明和访问入口都能直接阅读。

## 黑白主题

| 要素 | 黑色主题 | 白色主题 |
| --- | --- | --- |
| 基底 | 近黑背景与分层深色面板 | 微灰背景与白色面板 |
| 文字 | 浅灰正文、淡蓝重点 | 深靛正文、蓝色重点 |
| 点阵与线 | 暗灰点阵、克制细线 | 浅灰点阵、清晰细线 |
| 覆盖 | 蓝 / 红单元、浅色共同覆盖 | 蓝 / 红单元、深色共同覆盖 |
| 选区 | 浅色实线、方形节点 | 深色实线、方形节点 |
| Logo | 官方原图置于白色小底板 | 同一个官方原图 |

色彩只辅助表达；图例、边界、文字、字段同时保留，避免只靠颜色识别状态。

## 全站延伸建议

- **巡天详情：** 顶部解释该巡天能提供哪些产品与覆盖；下面分别列出版本、可用精度、原生单元、证据和官方入口。
- **版本 / 产品选择：** 使用紧凑列表，清楚显示选择状态、支持范围和限制，沿用点阵标记与细线分组。
- **来源详情：** 突出已知身份与空间依据。有身份但没有获取链接时仍显示记录，不能隐藏或捏造文件入口。
- **API / Key 页面：** 解释匿名预览、完整来源查询及导出的访问条件；使用统一表单和状态提示。
- **加载与空结果：** 点阵变化只表达界面状态。空结果说明当前筛选、范围或索引限制，不把未发布的数据表述为没有观测。
- **错误与精度提示：** 用简短说明和明确字段呈现 exact、estimated、entrypoint-only、truncated 等真实状态；实际精度跟随业务结果。

## 本稿边界

本稿基于仓库的页面结构与产品文档制作，未执行实际巡天查询、下载科学数据或启动业务环境。在线示例在当前环境无法直接访问，图中没有在线观测得出的实时状态。

静态设计稿完成后可据此评审页面方向；应用实现和接入真实数据属于后续工作。
