# 后续页面设计范围

依据当前页面源码和最新反馈梳理。**这是一份范围清单，不是已完成的页面设计稿。** 本轮先完成深色 Logo；后续以实际功能和信息密度为基础补齐页面。

## 采纳与保留

首页仅保留已认可的排版、下方示意图和 Tab 方块表达。导航栏目与首页内容 Tab 需要分别体现各自的选中状态，避免混淆。首页仍应保留真实目录统计、巡天深链和使用入口；示意图不能伪装为实时查询结果。

天球沿用现有版本。必须保留图层筛选、版本 / 产品 / 模态、实际覆盖单元、浏览与共同区域模式、相机工具、选择队列、检查器、连通区域、结果抽屉、来源详情、Key 解锁、分页、JSON / CSV 导出，以及原来的信息密度。以后只在明确的范围内统一颜色、图例、文字和边界，不以简化卡片替换详情。实际 HEALPix 几何和精度不能被装饰点阵覆盖。

## 管理台

管理台是完整的工作流程，需要分别设计总览、来源、任务、审核、发布和 API / Key 管理。保留当前登录、会话、能力状态、六个步骤 Tab、路径历史、刷新与自动更新；刷新不应丢失已展开内容和选择位置。

| 页面 / 路由 | 必须保留的信息与行为 | 设计重点 |
| --- | --- | --- |
| 总览 `/admin/overview` | 草稿 / 公开版本就绪度；巡天 / DR / 产品层级；真实分母与缺口；活动原生索引 | 保持高密度总览与层级浏览；零、未知、未加载分别表达；未知分母不画完成百分比 |
| 来源 `/admin/sources` | Connector 创建、类型、探测、编辑与安全详情；受管原生来源分组、筛选、版本；获取、校验、锁定快照、暂存导入 | Connector 和原生元数据来源分区；样例仅显示配置状态，不包含凭证 |
| 任务 `/admin/tasks` | 探索、MOC 探测、文件扫描、原生分块构建四个子 Tab；候选输入、ScanPlan、进度、错误、产出、候选索引构建 | 任务类型保持独立；成功扫描不等于发布；失败保留诊断与恢复入口 |
| 产品审核 `/admin/review` | 状态 / 审核资格筛选；阻塞原因；详情、证据、执行历史、说明草稿；实际 MOC order 门禁；逐项接受缺口；绑定当前版本的审核 | 展示是否可审核及原因；审核状态必须与当前版本和真实证据关联 |
| 原生索引审核 | 活动 / 候选绑定、锁定输入、制品差异、审核状态 | 与产品审核分成独立路径；支持清楚对比活动版和候选版 |
| 发布 `/admin/releases` | 产品发布计划、执行记录、选择与审核绑定；增量上传、完整性检查、网站验证；原生版本归档、激活、历史与恢复 | 审核、归档、发布、激活、验证分别展示；保留异步过程及失败明细 |
| API / Key `/admin/api` | LLM 配置 / 测试 / 停用 / 用量；Key 创建、一次性凭证、名称、期限、配额、用量、撤销 / 删除；调用记录 | 服务设置、Key 管理和调用审计分区；保留一次性展示与权限边界，不展示真实凭证 |

管理页同时适配独立品牌区域。键盘 Tab、方向键、Home / End 等当前交互应保留。

## 两个主题的共同原则

各页面需要黑色与白色两套稿，信息结构和能力保持一致。色彩用于区分类型与状态，同时保留文字、边界和图例。列表、证据和代码区的阅读优先于装饰。

没有真实查询或服务响应时，设计示例明确标注；不编造结果数量、完整库存、完成状态、可用链接或精度。来源清单与科学数据获取继续分开说明。
