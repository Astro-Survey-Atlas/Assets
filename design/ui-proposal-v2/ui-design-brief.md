# Astro Survey Atlas · UI 改进稿 v2

这版改进首先让用户知道项目能帮助自己做什么，再用统一的天文点阵语言呈现覆盖、重合和数据来源。核心路径是 **选天空 → 比较覆盖 → 找来源**。

这份设计基于当前仓库的 README、AGENTS.md、HANDOFF.md、首页、天球图册、巡天目录及详情、项目介绍、SDK 和公共样式。提供的线上地址在本次环境中被访问代理返回 403，因此没有将本地源码预览视为线上实测，也没有确认线上当前目录数量、查询结果或服务状态。视觉稿中的星带和覆盖图形属于概念示意，不是一次真实巡天查询。

## v2 更新：原始 Logo 与黑白主题

按反馈保留原始 Logo，直接复用仓库现有的官方完整图像 `site/public/asa-logo-long-fixed.png`，形状、蓝红配色及字标均不改变。设计文件中的 `official-logo.png` 与该原文件逐字节一致，不使用滤镜、反色或重描。黑色主题使用浅色品牌底板保证原彩色 Logo 的辨识度；白色主题沿用同一文件。

## 1. 项目应当怎样被理解

Astro Survey Atlas 的公开入口帮助用户回答：某片天空有哪些巡天数据，它们在哪里重合，这些覆盖对应哪些真实来源。

Assets 将公开巡天的版本、产品及空间覆盖放到同一张天球上，展示有依据的原生数据单元身份和官方访问入口，并导出 JSON/CSV 来源清单。研究者可以从区域逐步走向相关 Tile、brick、target、observation 等来源；普通访问者不需要先掌握这些术语。

Assets、Warehouse、Workspace 与 MOC-Core-SDK 的分工适合放在项目介绍与开发者材料中。它们解释系统怎样实现这条路径，不应成为用户学习路径的起点。

## 2. 当前页面的主要问题

1. **首屏价值不够具体。** “绘制天空。找到数据。”适用于很多天文工具；紧随其后的 DR、模态、Tile、brick、observation 和 JSON/CSV 又要求用户先有背景知识。
2. **用户任务和工程组件处在同一层。** 覆盖、MOC、反查、证据、Warehouse 和 Workspace 六张卡片并列，看起来能力很多，却难以看出从哪里开始。
3. **解释使用流程的位置太晚。** 真正展示选择、重合、来源的流程在架构介绍之后；组件职责又在两个位置重复。
4. **导航没有建立主次。** 首页、天球、目录、发布、术语、API、SDK、GitHub 与管理台共同争夺注意力。
5. **“下载计划”容易产生错误预期。** 用户需要先看到“来源清单”，理解导出里包含身份、出处和链接，实际科学数据由原始档案提供。
6. **天球中的操作过于依赖图标、快捷键和技术状态。** 图层、重合模式与来源结果需要有明确的可见入口；NSIDE、FOV、CAM 可以放在技术信息层。
7. **点阵目前主要用于首页装饰。** 当前首页画的是矩形点阵与 ASA 字样。它有像素特征，但尚未形成星带密度、天球形态及全站统一的视觉语言。

## 3. 首页的信息架构

### 第一屏：让用户知道为什么进入

**主标题**

> 同一片天空，有哪些巡天数据？

**说明**

> 在同一张天球上查看公开巡天覆盖，比较重合区域，找到对应的官方数据来源。

**操作**

- 主按钮：探索天球
- 次按钮：浏览巡天
- 轻量流程提示：选天空 → 比较覆盖 → 找来源

右侧及背景呈现青蓝、蓝紫、少量玫红像素构成的银河星带。文字区域保持低密度，图像区域逐渐聚集。图像标注“概念示意”，避免被误读为实际巡天覆盖。

首屏不引入尚未确认存在的坐标、天体名称搜索。开始入口连接现有天球与巡天/产品路径。

### 第二屏：一眼理解完整操作

用一个连续的视觉流程替代分散的能力介绍：

| 步骤 | 用户看到什么 | 简短文案 |
| --- | --- | --- |
| 01 选天空 | 选中巡天图层与关注区域 | 选择巡天和产品，查看它们覆盖的天空。 |
| 02 比较覆盖 | 不同颜色的覆盖与交集 | 将公开巡天放在一起，查看共同覆盖的区域。 |
| 03 找来源 | 来源身份、档案入口与导出操作 | 查看对应来源，访问官方档案，导出来源清单。 |

流程采用示意图，不填未经确认的命中数量、面积、精度或链接核验结果。术语解释通过小提示逐步补充。

### 第三屏：从感兴趣的巡天开始

展示现有目录所支持的巡天、发布版本和产品类型，并提供“在天球查看”。名字和产品类别优先于 HEALPix order 等技术参数。数据可用时展示真实目录内容；目录暂不可用或无数据时给出简洁说明，不填造数值。

### 第四屏：结果为什么可信

说明每个结果都保留来源与实际精度，能够区分覆盖结论、原生单元匹配和可访问链接。以一张来源卡的结构展示“身份 / 来源 / 精度 / 已知限制”，详细证据可以展开。

### 第五屏：更多使用方式

以小型入口连接发布包、开发者材料和项目介绍。组件架构只出现一次，不再重复六张能力卡和多段系统分工。

## 4. 全站页面如何延续

### 公共导航

建议主导航收为“探索天球 / 巡天目录 / 了解项目 / 开发者”。发布内容归入复用资源或对应入口；术语、源码和管理入口放入低强调位置。语言、主题按钮继续明确可识别，但不与主要操作竞争。

这是导航组织建议，保留现有页面与可访问路径，避免因改名造成内容丢失。

### 天球图册

- 左侧使用有标题的“巡天图层”面板，名字、版本、产品类型和勾选状态直接可见。
- 中央保留最大的天空视野，顶部用“查看覆盖 / 比较重合”显式标出模式。快捷键作为额外帮助。
- 右侧检查器按“谁覆盖这里？”“对应哪些来源？”“下一步去哪里？”组织结果。
- 来源卡突出巡天、版本、产品、原生单元与档案入口；order、ICRS/NESTED、输入快照及哈希进入可展开技术信息。
- 比较结果的选中区域使用边界、标签和图例同时表达，不只改变颜色。
- 导出操作写“导出来源清单”，结果不完整、截断或仅有入口时保留状态说明。
- 空状态指出具体下一步：选择一个巡天图层。错误状态保留已知身份并提示可以重试的操作。

### 巡天目录与产品详情

目录首先回答有什么可查：巡天名、版本、产品类型、覆盖可用性。保留现有文本搜索，使用更清晰的条目或表格；小型点阵覆盖图提供空间提示，状态带文字标签。

产品详情先给“这是什么 / 覆盖哪里 / 我能怎么使用”，并列“在天球查看”“官方档案入口”。下一层解释精度和限制，再展示方法、证据、哈希及开发者制品。保留产品的独立身份和深链能力。

### 发布与资源包

在页面开头解释 MOC、Resource Package 和来源清单各自的用途。发布条目展示真实版本、时间、所含内容、兼容信息及已有完整性校验信息，技术细节按需展开。下载按钮明确标出所下载的制品类型，避免将包或覆盖数据误称为科学影像下载。

### API / SDK / 项目介绍

API 先给一个真实支持的使用路径，例如获取已发布覆盖与按区域查来源，再进入接口表。认证、配额和完整查询的要求在相关操作处说明。SDK 解释离线空间处理库的职责，链接正式文档。代码区域保持常规高可读字体和可复制性。

项目介绍将四个组件的职责和数据流放在一张图里，以“为什么需要它们”连接到用户流程。首屏仍先说项目价值，再说组件。

### 管理界面

管理界面复用色板、细线、方形状态标识和微型空间预览，保持更高的信息密度。来源、候选、审核、归档与激活状态需要清晰可辨。点阵只用于辅助标识与空间内容，不能遮挡表格、日志和错误详情，也不能靠发光暗示某版本已审核或可激活。

## 5. 点阵视觉规则

用户参考图的主要特征是稀疏方形像素、银河式密度变化、青蓝到蓝紫及玫红的光色、局部明亮核心。设计沿用这些特征，并以清晰排版保持信息的主体地位。

| 元素 | 建议 |
| --- | --- |
| 基础背景 | 近黑蓝 `#070B14`；长篇文档与管理页面可用更实的深色面板 |
| 正文 | 偏白 `#E8EEF6`；次要文字保持足够对比度 |
| 主操作与部分覆盖图层 | 青色 `#68DAF2` |
| 次级覆盖图层 | 蓝紫 `#888DFF` |
| 对比图层及少量意象 | 玫红 `#D16DAA`；不与错误状态混用 |
| 结构 | 冷灰蓝细线、规整留白、方形或极小圆角 |
| 字体 | 标题与正文使用正常可读字体；坐标、版本、数量、状态使用等宽字体 |
| 发光 | 集中在天空像素与选中区域；正文、表格和大面积卡片保持稳定清晰 |

点阵延续到小型方形标识、图层图例、章节刻度、分隔符、微型 footprint 和选中状态。避免每个面板都铺满亮点，也不使用像素中文作为正文。

**装饰像素与真实 HEALPix 单元分别表达。** 首页银河是示意图；实际天球沿用球面上的 HEALPix 几何、真实阶数及科学覆盖边界。不能将平面方格或装饰亮点解释成实际科学像元，也不能用放大预览制造更细的覆盖结论。

### 可访问性与响应式

- 正文目标对比度至少 4.5:1，大字号文字和必要图形至少 3:1；最终配色需逐项验证。
- 巡天、选择、错误和精度状态同时使用文字、形状或边界，保证不依赖颜色识别。
- 键盘焦点保持明显，按钮和图层可通过键盘操作；图标有可识别的名称与可见提示。
- 避免星点闪烁和持续强动画；尊重 `prefers-reduced-motion`。概念星带可以采用静态展示。
- Canvas 覆盖图提供清晰说明，查询结果通过可读列表或表格呈现。
- 小屏让天空、图层和结果有明确的切换入口；结果抽屉保留关闭按钮及当前位置，不让多个浮层遮住全部地图。
- 亮色主题保持点阵结构与足够对比度，减少光晕，避免将暗色内容直接反相。

## 6. 数据与表达边界

1. 不虚构巡天、版本、产品数量、面积、命中记录、链接核验状态或查询精度。视觉样例明确标为示意。
2. 来源清单包含身份、证据和已有链接，不等于科学数据，也不暗示 Assets 代用户取回科学文件。
3. 已知来源即使没有可用链接，也应保留身份、证据和当前限制。
4. 覆盖精度、原生映射精度、库存完整性、链接可用性分别表达。`exact`、`verified` 和 `inventoryComplete` 不合并为一个笼统状态。
5. `exact`、`estimated`、`entrypoint-only`、`truncated` 和实际 order 随结果及导出保留；分页耗尽不自动代表库存完整。
6. 公开巡天内容与 Workspace 私有内容保持清晰边界，不将私有文件或覆盖引入首页和公共示例。

## 7. 建议优先级

| 优先级 | 改进 | 完成后的判断标准 |
| --- | --- | --- |
| P0 | 首页首屏文案与三步骤重排 | 初访用户能说出“比较巡天覆盖并找到来源”，知道第一步点哪里 |
| P0 | 全站导航建立主次 | 探索与目录成为明显入口，架构与开发者内容容易找到但不阻断主要路径 |
| P0 | 来源清单、精度与限制的表达 | 用户能区分覆盖结论、来源身份、链接和实际科学数据 |
| P1 | 统一点阵色板、形状和排版 | 首页、天球、目录、详情、发布、文档与管理页具有共同语言且保持可读 |
| P1 | 天球的显式图层、模式与来源面板 | 不依赖快捷键也能完成选天空、比较覆盖、找来源 |
| P1 | 目录与产品详情的信息层级 | 先看到产品用途、覆盖与下一步，再深入技术证据 |
| P2 | 细节动效、示意流程与小型覆盖预览 | 增强空间理解，不影响读取数据或制造未验证的结果 |

第一版视觉稿重点展示首页和天球图册：前者检验项目是否被解释清楚，后者检验这种点阵语言能否支持真实工作界面。确认这两个界面的方向后，再将同一规则延续到其余页面。
